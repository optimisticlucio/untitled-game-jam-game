# Notes for Claude

Game jam project in Godot 4.7 (GDScript). Several people work on it with Claude. The design is in README.md and IDEAS.md and changes often, so read those rather than relying on this file for design.

- If a request conflicts with README/IDEAS, or looks likely to cause problems later, say so before building it.
- Keep this file short: only conventions and decisions that the code depends on. Ideas belong in IDEAS.md.

## Decisions

- Renderer: Compatibility, so a web build stays possible. Physics: Jolt.
- Portrait, designed for 720×1280 (9:16).
- Collision layers: 8 = `pick` (instruments' enlarged grab areas), 9 = `drop_zones` (flat areas at table level, see `gameplay/tool_grabber.gd`).
- Gameplay code never names specific instruments. It finds `SurgicalTool` scenes at runtime with `SurgicalTool.scenes_by_id()`; which tools exist is the artists' call.
- The tray's size and shape come only from its `Zone` collision shapes (boxes/cylinders) in `gameplay/tray.tscn`. Code asks the `Tray` (`contains`, `floor_height`, `random_point`, `nearest_placement`, `on_screen`) and never assumes dimensions. With its `camera` set, tools are only laid out or put back where their middle is on screen (the tray is wider than the screen).
- Levels are data: one `LevelData` `.tres` per level in `levels/`, naming tools by `id` (saved as the id, picked in the inspector from a dropdown filled by `SurgicalTool.ids()`; never an enum, which would save numbers). Tool lists where a tool can appear more than once are `Dictionary[StringName, int]` (tool id → count), listed in `LevelData.COUNTED_LISTS`. The tutorial asks for each tool once, so `tutorial_ids` is a plain list, played by `levels/level.tscn`. Each level has its own `id`; scores are saved under it, never under the file name. The one list of levels, in order, is `levels/levels.tres` (`LevelList`); code gets levels from `LevelList.all()`, never by scanning the folder. The selector sets `LevelList.chosen` for `level.tscn`. New per-level settings go on `LevelData`, not in a new scene or subclass.
- UI is English for now, through `tr()`. The look lives in one theme, `ui/theme.tres`, plus `ui/icons/` and `ui/art/` (artists restyle there). Every `Button` uses Julia's painted button (`ui/art/button.png`, lit `button_pressed.png` when pressed), 9-sliced so one texture fits any size; icon-only buttons use the `IconButton` variation. Button text is drawn by Godot in Nunito (`ui/fonts/`, OFL), never baked into images. The screens are `ui/main_menu.tscn` (Play, Pocket Guide, Leaderboard, Settings), `ui/level_select.tscn`, `ui/pocket_guide.tscn` and `ui/hud.tscn`, all generated at first but fine to edit by hand.
- Scores: the level's `Scoring` resource (`LevelData.scoring`: `PointScoring` or `TimeScoring`, tuned in `gameplay/scoring/*.tres`) turns a `RunRecord` into a score. `ScoreBoard` (`gameplay/score_board.gd`) only saves and ranks: each name's best per level id and scoring kind in `user://scores.cfg`, plus sample rivals (marked as samples) scored by the same rule. A new way of scoring is a new `Scoring` subclass, not changes to `ScoreBoard`. The level shows `ui/level_result.tscn` at the end, and `ui/leaderboard.tscn` has one board per `LevelData`. Names only, no titles: players are any OR staff.
- Audio: players use the `Music` or `SFX` bus (`default_bus_layout.tres`). `SettingsPanel` saves both volumes to `user://settings.cfg`. UI sounds play from the `UiSounds` autoload (`ui/ui_sounds.tscn`, players only, reached as `/root/UiSounds/<Name>`) so a click survives a scene change; level sounds are players under `Sounds` in `levels/level.tscn`. Sound files and what plays when: `assets/sounds/README.md`.
- Shader compiling: the `ShaderWarmUp` autoload (`gameplay/shader_warm_up.gd`) draws `level.tscn`'s 3D nodes with every tool, invisibly, on the first frame, under the boot splash. Without it a fresh install froze for seconds when the first tray appeared. Anything drawn in the level should be in `level.tscn` or reachable from it (tools, tray, grabber, `ToolPreview`), so it's warmed too.
- Export presets: add `addons/godot_ai/*` and `dev/*` to "Filters to exclude files". The plugin already strips its autoload from exports, but its files still ship otherwise.
- Lookalike pairs will live in one central list, not on each tool (avoids out-of-sync data). Not built yet.
- Instrument naming language: undecided. Refer to tools by `id` in code, and pass display names through `tr()`.
- Tool pictures in dialogs: render the model at runtime (`ui/tool_preview.tscn`, slow spin). No PNGs from the artists.
- The surgeon (`gameplay/surgeon.tscn`, Julia's Spine animation as frames) is an `AnimatedSprite3D` in the level's 3D world facing the camera, not UI, so held and handed tools show in front of him and the tray hides his lower body. He stands just behind the tray's far rim, below the table, so the table's material doesn't write depth (`render_priority` -1) and only the tray covers him. `Target` (with `HandOffZone`) sits on his hand: move them together. Handed tools ride his hand and he throws them (`ToolGrabber.surgeon`, timing in `Surgeon.correct_steps`/`wrong_steps`).
- The level's background is Julia's room picture (`ui/art/level_background.png`) on the `Room` CanvasLayer at layer -1. The environment's background is Canvas, so that layer is drawn behind the 3D world; light still comes from the sky. The table's mesh is hidden (its collision stays), so the room shows around the tray.

## Surgical tools

- `SurgicalTool` is only for items the player must recognize and hand over. The silly items count (they're `Speciality.SILLY`). Scenery and props don't: trays, tables, dishes, the doctor, the patient. Those are ordinary scenes, and never go in `tools/`.
- Tool scenes live in `tools/` (subfolders fine). Code reads the path from `SurgicalTool.FOLDER`, never a literal.
- Each tool is an inherited scene of `tools/surgical_tool.tscn`, with its model and `CollisionShape3D` children added, and its data set in the `SurgicalTool` exports. No separate data files per tool.
- Collision: boxes or convex shapes only. Never concave/trimesh: tools are dynamic bodies.
- `SurgicalTool.Speciality` and `SurgicalTool.Category` (what the tool does, which groups the Pocket Guide) are append-only, because scenes store them as numbers.
- Models lie flat as they would on a tray (Y up), at real size in meters.
- The instrument scenes (`tools/<slug>.tscn`, `assets/instruments/`) are generated from Julia's Blender export by `dev/instruments/build_instruments.gd`, so don't hand-edit them. See `dev/instruments/README.md`.
- Grabbing: each tool has a `Pick` Area3D on collision layer 8 only (inflated shapes). Raycast that layer with `collide_with_areas`.
- `project.godot` sets Jolt penetration slop 0.001 and speculative distance 0.004; the defaults (0.02) sink millimetre-thin tools.
- Looks: tools and the tray get their materials at runtime from `ToolLook` (`gameplay/tool_look.gd`; shaders and textures in `assets/shaders/`), with a new random tint, scratches, stains and blood placement every tray, so tools are recognised by shape only. Don't set materials in tool scenes. Julia tunes the values in her browser shader lab; `dev/shader_lab/lab.tscn` renders them in Godot. The held tool's highlight (neon outline, glow, floating stars) is tuned with the sliders in `dev/neon_preview/neon_preview.tscn`, which save straight into the files the game uses.
- Shaders never size things in raw pixels, so the look holds on any screen and tool size: screen patterns in screen widths (`VIEWPORT_SIZE.x`), outline widths as a share of the camera distance, so they're equally thick on every tool (`gameplay/outline_width.gdshaderinc`), tool wear sized to the tool's length, and fine noise and highlights softened with `fwidth()` where they get smaller than a pixel. Check with `dev/shader_lab/scale_shot.tscn` at two `--resolution`s.
